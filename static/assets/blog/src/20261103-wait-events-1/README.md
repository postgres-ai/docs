# Figures for "What your Postgres is waiting for, and why the dashboard can't tell you"

Everything in `static/assets/blog/20261103-wait-events-1-*` is generated by the
scripts in this directory from the published raw data. Nothing is drawn by hand,
so restyling means editing a script and re-running it.

## Files

| Output (in `static/assets/blog/`) | Generator | Data |
|---|---|---|
| `20261103-wait-events-1-sampling.gif` | `sampler_gif.py` | synthetic timeline defined in the script |
| `20261103-wait-events-1-sampling.svg` | `svg_figures.py` (same picture, CSS-animated SVG) | same |
| `20261103-wait-events-1-latency-tail.gif` | `tail_gif.py` | `data/latency.json` |
| `20261103-wait-events-1-profile-vs-tail.svg` (and `-dark.svg`) | `svg_figures.py` | `data/r1b.json` |
| `20261103-wait-events-1-one-slow-request.gif` | `request_gif.py` | `data/r1b.json` |
| `20261103-wait-events-1-one-slow-request.svg` (static version) | `svg_figures.py` | `data/r1b.json` |

`data/*.json` is produced by `extract_data.py` from the raw logs of case 1:
`tests/results/checkout-tail-20261022/raw/` in
[DmitryNFomin/pg_wait_tracer](https://github.com/DmitryNFomin/pg_wait_tracer/tree/master/tests/results/checkout-tail-20261022)
(scripts and summaries on `master`; the pgbench logs and trace rings in the
[`evidence-20261023` release](https://github.com/DmitryNFomin/pg_wait_tracer/releases/tag/evidence-20261023)).

## Regenerate

```sh
python3 -m venv .venv && .venv/bin/pip install matplotlib pillow   # ffmpeg must be on PATH
cd static/assets/blog/src/20261103-wait-events-1
# data (optional, data/*.json is committed):
#   tar xzf checkout-tail-20261022-raw.tar.gz -C <pg_wait_tracer>/tests/results/
#   ../../../../../.venv/bin/python extract_data.py <pg_wait_tracer>/tests/results/checkout-tail-20261022/raw data
V=../../../../../.venv/bin/python; O=../..
$V sampler_gif.py $O/20261103-wait-events-1-sampling.gif /tmp/fr_sampler
$V tail_gif.py    data/latency.json $O/20261103-wait-events-1-latency-tail.gif /tmp/fr_tail
$V request_gif.py data/r1b.json     $O/20261103-wait-events-1-one-slow-request.gif /tmp/fr_request
python3 svg_figures.py data $O
```

Each GIF exists in a light and a dark variant (`…-dark.gif`); the post shows the one
matching the reader's theme through Docusaurus's `ThemedImage`. Set `THEME=dark` in
the environment to render the dark variant:

```sh
THEME=dark $V sampler_gif.py $O/20261103-wait-events-1-sampling-dark.gif /tmp/fr_sampler_dark
THEME=dark $V tail_gif.py    data/latency.json $O/20261103-wait-events-1-latency-tail-dark.gif /tmp/fr_tail_dark
THEME=dark $V request_gif.py data/r1b.json     $O/20261103-wait-events-1-one-slow-request-dark.gif /tmp/fr_request_dark
```

## Conventions

- Palette (light surface `#fcfcfb`): blue `#2a78d6`, orange `#eb6834`, aqua `#1baf7a`,
  yellow `#eda100`, violet `#4a3aa7`; text `#0b0b0b` / `#52514e`; grid `#e4e3df`.
  Dark palette: surface `#1a1a19`, blue `#3987e5`, orange `#d95926`, aqua `#199e70`, yellow `#c98500`, violet `#9085e9`; text `#ffffff` / `#c3c2b7`; grid `#383835`. Each SVG is written twice, light and `-dark`, because an `<img>` SVG cannot see the site theme; the GIFs use the `THEME` variable above.
- GIFs: 1100 px wide, 12 fps, 128-colour palette from ffmpeg `palettegen`, no dither,
  looped; each shows live counters from the first frame and holds its last frame
  for 4–4.5 s so the conclusion can be read before the loop restarts.
- Numbers in the figures are taken from the data files, never typed in; if a
  number in the post changes, change the data and regenerate.
